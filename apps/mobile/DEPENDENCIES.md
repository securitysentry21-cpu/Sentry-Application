# Guard app dependencies

Every dependency added for the guard app framework (SEC §14, CLAUDE.md). All are pinned to exact
versions. Expo libraries were added with `npx expo install` (the SDK 57 versions from
`expo/bundledNativeModules.json`), then pinned. `node scripts/check-licences.ts` passes for the whole
tree (606 packages); `node scripts/audit-deps.ts` reports no new advisories. No dependency has an
install script, so `allowBuilds` in `pnpm-workspace.yaml` is unchanged.

"Native permissions" lists what a library declares in its Android manifest or adds through its
config plugin, and what `app.config.ts` does about it. The final list is checked with
`npx expo config --type introspect` (see README, "Native permissions").

Not added, deliberately:

- **No navigation library**: a handful of screens, navigated by state (`src/ui/App.tsx`).
- **No Expo push service**: `expo-notifications` is used only for the phone's native Firebase token and notification channels. Pushes come straight from our server to Firebase (D-26); the server side is Phase 8's `POST /me/push-token`, shift notices and "SOS acknowledged".
- **No `expo-haptics`**: React Native's `Vibration` (with `VIBRATE`) covers the haptic ticks.
- **No `expo-device` / `expo-application`**: `Platform.constants` gives the OS version, manufacturer
  and model; `expo-constants` gives the app version.
- **No `expo-dev-client`**: development builds are React Native debug builds (`expo run:android`, or
  the EAS `development` profile with `:app:assembleDebug`).
- **No `expo-updates`**: there are no over-the-air updates (ARCH §19.7).
