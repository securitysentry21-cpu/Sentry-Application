# Sub-processors and other third parties

> Prepared by an AI coding assistant from the code and the specifications, not by a lawyer. Nothing here is final. Open points are marked `[OWNER TO CONFIRM: ...]` and `[LAWYER: ...]`.

This list names every outside company that touches data in the service. It is an annex to the Data Processing Agreement (`DATA_PROCESSING_AGREEMENT.md`) and is linked from the privacy policy.

**Terms used.** "SENTRY" is the working name of the service and of the company that runs it (`[COMPANY LEGAL NAME]`). The "customer" is the security company that uses the service. A "cell" is one complete deployment in one region (DECISIONS D-13).

**Status words.** _In use_ means it runs in the test environment today. _Decided, not built_ means the owner has chosen it but it does not run yet. _Not chosen_ means there is no provider yet. _Planned_ means it waits on something else.

Important: the only environment that exists today is a **test environment in Sydney with test data only. No real guard has used the service.** Source: `docs/DECISIONS.md` (Infrastructure, agent-decided 2026-10-09); `infra/terraform/env/test.tfvars`.

### Notes

**A. Client IP addresses in logs `[OWNER TO CONFIRM]`.** The API's logger redacts tokens, codes, coordinates, text and phone numbers (`apps/api/src/logger.ts`). It does not list IP addresses. Fastify's default request log line includes the client address (`node_modules/fastify/lib/logger-pino.js`, `remoteAddress`). So request logs in CloudWatch very likely hold IP addresses for 30 days. Audit records also keep an IP address and browser string for audited actions, for 24 months (`docs/ARCHITECTURE.md` §6.3, `audit_logs`). The privacy policy says so. Please confirm by reading a real log line.

**B. What the test environment is.** The test environment is in Sydney because the first AWS account is of a simplified type that allows only that region (`docs/DECISIONS.md`, Infrastructure). It holds test data only. Real guards will use production in Frankfurt.

**C. Backups.** Only the **database** backups are copied to Ireland (`aws_db_instance_automated_backups_replication`, `infra/terraform/cell/database.tf`). `docs/ARCHITECTURE.md` §19.6 and §19.8 also say incident photos and files are replicated to Ireland and versioned. The Terraform code has no bucket replication or versioning for the files bucket (`infra/terraform/cell/attachments.tf`). This list therefore claims **no file replication.** If the owner wants it, it must be built first.

## 4. Things that are deliberately NOT sub-processors

- **No analytics, advertising or tracking service** is in the guard app or the dashboard. The Android advertising-ID permission is blocked in the build. Source: `apps/mobile/android-permissions.ts` (`BLOCKED_ANDROID_PERMISSIONS`); `apps/mobile/app.config.ts` (`NSPrivacyTracking: false`); `apps/mobile/DEPENDENCIES.md`.
- **No third-party crash-reporting service.** The guard app sends a scrubbed error report to **our own API only.** The API writes it to its service log (AWS CloudWatch Logs, #1a), kept 30 days and then deleted. It is not stored in a database table. The report holds: its kind (unhandled error, render error or unexpected close), the error type name, source-file:line:column frames of our own app code, app version, OS version, platform, a fatal flag and a timestamp, plus the device ID and organization ID as opaque IDs. It holds no message text, names, phone numbers, locations or incident text. Source: owner decision in `docs/DECISIONS.md` (Phase 10, crash reports: "our own server only"); the build brief of 2026-11-08 for the log and the 30-day retention; `apps/mobile/src/core/log.ts` and `infra/terraform/cell/services.tf` (`retention_in_days = 30`) for the existing scrubbing and retention. `[OWNER TO CONFIRM: the crash-report code was still being written when this draft was made.
