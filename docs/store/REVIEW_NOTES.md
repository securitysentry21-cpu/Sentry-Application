## 2. How the sign-in works (for the owner)

| Fact                                                                                                                                 | Source                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| A supervisor, administrator or owner issues a single-use code from the dashboard for one guard. It is shown as a code and a QR code. | `apps/api/src/routes/enrollment.ts`; `docs/DECISIONS.md` (round 6, "No SMS aggregator yet") |
| The code expires after **7 days** and allows **5 wrong tries**.                                                                      | `docs/SECURITY_AND_INVARIANTS.md` §5, §9; `enrollment.ts` (`MAX_ATTEMPTS`)                  |
| The code is bound to the guard's phone number. The app sends the number the reviewer types; it must match.                           | `docs/SECURITY_AND_INVARIANTS.md` ADV-A11                                                   |
| At most **3 codes per guard per day.**                                                                                               | `enrollment.ts` (`CODES_PER_DAY`); `SEC` §9                                                 |
| Codes go only to **+92** numbers, unless the operator allows another country. The demo guard's number must follow that rule.         | `enrollment.ts`; `docs/DECISIONS.md` (Pilot scale)                                          |
| **One active phone per guard.** Enrolling a second phone on the same guard revokes the first.                                        | `docs/PRODUCT_SPEC.md` §4.5; D-05, D-31                                                     |
| The phone's session is then bound to the phone. There is no password.                                                                | `docs/DECISIONS.md` D-02, D-30                                                              |

**Practical consequences**

- Make **one demo guard per reviewer team.** At least: one for Google Play, one for Apple, one spare. If both stores shared one guard, the second reviewer's enrollment would sign the first one out.
- Issue the code **close to submission.** Reviews can take days. If the code lapses, issue another (up to 3 a day per guard) and send it through the console's reply box.
- Keep the **demo shift startable**. See section 3.

## 6. If something goes wrong

| What the reviewer sees                      | Why                                             | What to do                                                                                                           |
| ------------------------------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| "The code or the phone number is not right" | A typo, or the number does not match            | Check the number against the form                                                                                    |
| "This code has expired or was already used" | 7 days passed, or another reviewer used it      | Issue a new code                                                                                                     |
| "Too many attempts"                         | 5 wrong tries on the code                       | Wait, or issue a new code                                                                                            |
| "No location yet" or low accuracy           | Indoors or emulator                             | Reviewer moves near a window; on an emulator, send a location                                                        |
| "Update the app"                            | The server's minimum version is above the build | Match the build to the server configuration before submitting                                                        |
| Cannot start the shift                      | No startable demo shift                         | Section 3                                                                                                            |
| Location flagged as fake (emulator)         | The phone reports a mock location               | The shift still runs; the dashboard raises a "suspicious location" flag (`PRODUCT_SPEC.md` §8.5). Tell the reviewer. |
